# 연결 검증 현황 (2026-10-03)

## 확인한 범위

실제 로컬 MySQL에서 롤백형 API 시나리오를 검증했다. 고객 인증은 테스트 의존성으로 대체했고 직원 처리는 서버 함수를 호출했으므로, 직원 앱·실제 로그인·화면 조작까지의 종단간 검증은 아니다.

- 주문 예약, 데모 결제, 쿠폰 사용, 포인트 사용 및 재시도
- 출고, 대리점 도착, 수령, 고객 소유 배송 조회
- 구매확정 전 리뷰 작성 차단, 구매확정 후 반품·환불 차단
- 리뷰 최초 작성 1,000P, 삭제 후 재작성 중복 지급 방지
- 삭제 리뷰 공개 제외 및 고객·주문 식별 정보 비노출
- 일반 결제와 포인트 전액 결제의 부분 반품·환불·재고 복구·포인트 복원
- 포인트 만료 작업 및 배치 재실행

검증 명령: backend의 `verify_checkout_benefits.py`, `verify_checkout_benefits.py --zero-cash`, `verify_maintenance.py`.
검증 데이터는 마지막에 롤백한다. 이미 적용한 스키마 변경은 롤백 대상이 아니다.

## 남은 항목

- 서버 모드 내 리뷰 수정·삭제 접근 복구 완료: 공개 리뷰 ID와 인증된 내 리뷰 ID를 로컬에서 대조하며 처리 후 목록·평점을 갱신한다. 실제 기기 편집·삭제 시연은 별도 확인 필요.
- 결제 화면 대리점 연락처·주소·요일별 운영시간 DB 연결 완료. 자치구당 하나의 대리점 운영으로 확정하여 대리점별 선택은 추가하지 않는다. district_code UNIQUE 제약은 추가하지 않는다.
- Firebase 실제 상태 전송·수신·보안 규칙 배포 검증: 팀원 담당으로 보류.
- 직원 검수·환불·출고 처리의 실제 화면 연결 및 직원 인증 시연.
- 공개 리뷰 사진 확대·페이지 이동, 실제 고객 로그인부터 구매까지 기기 UI 시연.
- 생일 쿠폰 정책·발급, 재입고 감지·알림 발송 등 배치 연결은 추가 점검 필요.

결제는 데모이며 실제 결제대행사 환불을 실행하지 않는다. 현행 반품 신청은 주문당 한 번만 허용한다.

## 대리점 데이터 확인

`backend/verify_pickup_branches.py`는 데이터를 변경하지 않고 활성 자치구 중복, 코드 매핑, 운영시간 등록을 확인한다.
현재 로컬 DB는 성동구 활성 대리점 1개이며 중복 없음, 코드 매핑 정상, 운영시간 7일 등록 상태다. 서울 25개 자치구의 실제 대리점 데이터가 모두 등록된 것은 아니다.
