# 로컬 쇼핑 기록의 계정 분리

수정 대상은 D 드라이브 `mysql-integration` 고객 앱입니다. 서버, MySQL 데이터,
ERD, 직원 앱은 이 변경으로 수정하지 않습니다.

## 저장과 전환

- 로그인 회원: Firebase UID에 해당하는 `firebase:<UID>` 저장공간 사용.
- 비로그인: 이 기기의 새로운 `guest:v2` 저장공간 사용.
- 이메일/Google/카카오/네이버 로그인, 회원가입, 앱 시작 시 로그인 복원,
  로그아웃에서 목록을 비우고 실제 계정의 찜·최근 본 상품·장바구니를 다시 읽음.
- 비회원 기록을 로그인 회원에게 자동으로 합치지 않음.
- 같은 이메일이라도 Firebase UID가 다르면 서로 다른 계정으로 취급.
- 저장/조회 시작 시 계정을 고정하고, 이전 계정의 늦은 결과는 현재 UI에 적용하지 않음.
- 전환·로컬 조회 실패 중에는 빈 목록이나 이전 계정 목록으로 저장하지 않음.
  조회 실패는 화면의 `다시 시도`로 복구할 수 있음.

## 기존 공용 기록

과거 앱은 로그인 여부와 관계없이 `guest`로 기록했습니다. 이 데이터는 누구의
기록인지 판단할 수 없으므로 삭제하거나 어느 회원에게도 자동 이관하지 않습니다.
기존 SQLite 행을 그대로 보존하되 새 회원/비회원 화면에서는 표시하지 않습니다.
`owner_key` 컬럼이 이미 있으므로 SQLite 스키마 변경도 필요하지 않습니다.

## 에뮬레이터에서 확인

서버 터미널은 그대로 두고, 고객 앱 실행만 중단했다가 다음 명령으로 다시 실행합니다.
앱 데이터 삭제 또는 제거는 하지 않습니다.

```powershell
cd D:\grace2\shupick\mysql-integration
& D:\grace2\flutter\flutter\bin\flutter.bat run -d emulator-5554 --dart-define-from-file=social-login.local.json
```

1. 카카오 계정에서 찜·최근·장바구니가 처음에는 비어 있는지 확인.
2. 상품 하나 보기, 찜 추가, 장바구니 추가.
3. 로그아웃 후 기존 이메일 계정 로그인 → 카카오에서 추가한 기록이 없는지 확인.
4. 다시 같은 카카오 계정 로그인 → 2번 기록 복원 확인.
5. 앱 실행을 완전히 중단하고 재실행 → 같은 UID의 기록 복원 확인.

새 변경 이후 기록은 **현재 기기 안에서만** 계정별로 유지합니다. 다른 기기와의
동기화나 MySQL `favorites`/`product_views`/`cart_items` API 연결은 별도 작업입니다.
주문·문의 등 기존 서버 데이터는 삭제하거나 옮기지 않습니다.
