# 서울 25개 자치구 픽업 대리점

각 자치구에 `SHOEPICK ○○점`을 하나씩 등록합니다. 주소는 `서울특별시 ○○구 가상로 101, 1층` 형태, 연락처는 `02-0000-1001`부터 구성한 가상 정보입니다. 실제 대리점 위치나 전화번호가 아닙니다.

운영시간은 월~토 **10:30 - 20:00**, 일요일은 **휴무**입니다. 주문할 때 자치구를 선택하면 해당 지점의 이름·주소·연락처·요일별 시간을 표시하고, 배송 조회에서도 같은 DB 정보를 사용합니다.

## 팀원 DB에 적용

백엔드 설정의 연결 대상을 확인한 뒤 `backend` 폴더에서 실행합니다. 아래 호스트와 DB 이름은 로컬 예시이며 팀 DB에 적용할 때는 실제 대상 값으로 바꿔야 합니다.

```sh
# 미리보기만 수행
python apply_seoul_pickup_branches.py

# 등록·수정을 검사한 뒤 모두 롤백
python apply_seoul_pickup_branches.py --check --expect-host 127.0.0.1 --expect-database shupick_v2

# 실제 반영
python apply_seoul_pickup_branches.py --apply --expect-host 127.0.0.1 --expect-database shupick_v2
```

기존 지점 ID와 코드는 보존하며 이름·주소·연락처·요일별 시간·활성 상태를 맞춥니다. 가상 주소에 실제 위치가 연결되지 않도록 좌표는 비웁니다. 성동점은 `SEL-SD`, 강남점은 신규 등록 시 `SEL-GN`을 사용합니다. 다른 구에 기존 지점이 있으면 그 지점 ID와 코드를 유지합니다. 구당 지점이 여러 개라면 임의로 선택하지 않고 오류로 중단합니다.

누락된 지점만 새로 등록하며 기존 주문·재고·직원 배정은 변경하지 않습니다. 적용 전 지점과 운영시간 기록은 Git에서 제외된 `backend/.local/branch-backups/`에 저장합니다. 이는 전체 DB 백업이 아닙니다.

`GET /branches/pickup`에서 서울 자치구 25개와 지점별 운영시간 7개를 확인하세요. 등록 후 주문 화면에 다시 진입하면 최신 목록을 읽습니다. Git으로 코드만 받는다고 팀원의 별도 DB에 지점이 등록되지는 않습니다.
