# 상품 상세 추천

상품 상세의 추천 카드를 누르면 해당 상품 상세로 이동합니다. 상품 번호에 고정된 예시 목록을 사용하지 않고 현재 DB 상품과 조회 기록으로 추천합니다.

## 실제 고객 공동 조회

`GET /products/{product_id}/recommendations?limit=4`는 로그인 없이 조회할 수 있으며, 최대 10개까지 반환합니다.

- 최근 30일의 `customer_interaction_events` 중 `VIEW`만 사용합니다.
- 같은 고객의 같은 앱 실행 세션에서 30분 이내에 함께 조회한 상품을 집계합니다. 앞뒤 조회 모두 포함합니다.
- 한 고객이 반복 조회해도 한 번만 집계하며, 서로 다른 고객 2명 이상이 함께 조회한 상품을 우선합니다.
- 현재 상품, 판매 비활성화 상품, 주문 가능한 본사 재고가 없는 상품을 제외합니다.
- 키즈는 키즈 상품을, 남성·여성은 해당 대상 또는 공용 상품을 추천합니다. 공용 상품은 성인 상품을 추천합니다.
- 공동 조회 수, 같은 세부 종류, 같은 상위 종류, 같은 대상, 같은 브랜드, 가격 차이 순으로 정렬합니다. 부족한 자리는 유사 상품으로 채웁니다.
- 고객 UID·이름·세션·개별 조회 이력·조회 수는 응답에 포함하지 않습니다. `coViewedProductIds`는 공동 조회 기준으로 선택된 상품 ID만 표시합니다.

로그인 회원이 상세를 열면 기존 `/interactions` 전송 큐에서 조회 기록을 저장합니다. 비회원은 분석 조회 기록을 서버에 저장하지 않지만 추천 조회와 로컬 최근 본 상품은 사용할 수 있습니다. 큐 전송에 실패한 기록은 연결 복구 후 재전송됩니다.

## 조회 기록이 부족한 경우

실제 공동 조회 상품이 있을 때 제목은 **이 상품을 본 고객이 많이 찾아본 상품**입니다. 기록이 부족할 때는 **함께 둘러보기 좋은 상품**으로 표시하여 유사 상품 추천을 실제 고객 인기 기록처럼 보이지 않게 합니다.

추천 API에 연결하지 못하면 앱이 현재 불러온 상품 목록에서 종류·대상·가격을 비교하여 추천합니다. 이 로컬 대체 추천은 최신 재고를 보장하지 않으며 구매 옵션 화면에서 서버 재고를 다시 확인합니다. 서버 응답이 정상적으로 빈 목록을 반환하면 품절 상품으로 채우지 않습니다.

추가 DB 테이블은 필요하지 않지만 기존 `015_customer_interaction_events.sql`이 적용되어 있어야 합니다. 서버 코드를 변경한 후 FastAPI를 재시작하세요. 별도 DB를 쓰는 팀원과 조회 기록은 자동 공유되지 않습니다.

## 확인

```sh
# backend 폴더
python -m pytest tests/test_recommendations.py tests/test_products.py tests/test_interactions.py -q

# 프로젝트 루트
flutter test test/product_recommendations_test.dart test/api_product_repository_test.dart test/actual_product_options_test.dart
```

로컬 MySQL과 초기 상품 10개가 준비된 경우 `SHOEPICK_MYSQL_TESTS=1`을 설정하고 `python -m pytest tests/test_recommendations_mysql.py -q`로 실제 SQL 집계도 확인할 수 있습니다. 이 검사는 임시 테이블의 조회·재고만 사용하고 테스트 데이터를 실제 테이블에 저장하지 않습니다.

신규 상품은 유사 상품으로 표시됩니다. 서로 다른 로그인 고객이 같은 실행 세션에서 해당 상품과 다른 상품을 함께 조회하면 다음 상세 진입부터 공동 조회 추천으로 표시됩니다.
