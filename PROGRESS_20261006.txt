1. 프로젝트 구성과 데이터 연결
- 고객 앱: Flutter의 lib/에서 화면과 상태를 관리합니다.
- 공통 백엔드: backend/의 FastAPI를 통해 MySQL에 접근합니다.
- SQLite: 기기의 앱 설정, 장바구니·찜·최근 본 상품 및 상품 캐시를 관리합니다.
- 고객 인증: Firebase Authentication의 UID를 MySQL customers와 연결합니다.
- 직원용 공통 API에는 권한 기반 문의 조회·답변, 주문·픽업·반품 등 업무 기능이 있습니다.
  직원용 앱 화면 전체가 이 고객 앱 저장소에 구현된 것은 아닙니다.

7. 장바구니와 상품 상세의 실제 사이즈 옵션
- 장바구니와 상품 상세의 고정 사이즈 목록을 제거했습니다.
- GET /products/{product_id}/options로 상품별 색상·사이즈·재고를 조회합니다.
- MySQL product_variants 및 본사 재고 조회 결과를 기존 API가 전달합니다.
- 선택한 색상에 맞는 사이즈를 숫자 순서로 표시하고 중복 옵션을 정리합니다.
- 품절 옵션을 표시하고 장바구니에서는 품절 옵션 선택을 제한합니다.
- 색상 변경 시 현재 사이즈가 존재하면 유지하고, 없으면 해당 색상의 주문 가능한 사이즈로 변경합니다.
- 서버에서 삭제된 저장 옵션은 안내하고 유효한 옵션으로 변경할 수 있게 했습니다.
- 조회 중 표시, 빈 옵션 안내, 조회 실패 후 재시도를 제공합니다.
- Dropdown의 선택값 245가 목업 목록에 없어 발생하던 AssertionError를 해결했습니다.

8. 회원가입과 MySQL 프로필
- 이메일 회원가입 화면에 이름과 전화번호 TextFormField를 추가했습니다.
- 생년월일은 년·월·일 드롭다운으로 선택합니다.
- 월별 일수와 윤년을 반영하며 연도·월 변경으로 유효하지 않게 된 일자는 다시 선택합니다.
- 필수 입력, 이름 길이, 전화번호 형식, 미래 생년월일을 검증합니다.
- 이름은 Firebase displayName과 MySQL customers.customer_name에 반영합니다.
- 전화번호와 생년월일은 /auth/customer/sync를 통해 customers.phone, birth_date에 저장합니다.
- 후속 로그인에서 생략된 전화번호·생년월일이 NULL로 덮어써지지 않도록 백엔드를 보완했습니다.
- Firebase 계정 생성과 MySQL 프로필 저장은 별도 단계입니다.
  MySQL 연결 실패 시 Firebase 계정만 생성될 수 있으며 로그인 때 프로필 동기화를 다시 시도합니다.

- 문의 조회·답변 API는 SUPPORT_MANAGE 권한이 있는 직원에게 제공됩니다.
- 주문하기의 '픽업 대리점' 제목 아래에 16px 간격을 추가했습니다.
- 주문 상품을 둥근 카드로 변경하고 상품명·옵션·수량·금액 배치를 정리했습니다.

10. 기획전 예외 수정
- '이번 주 특가'와 '계절의 신발'에서 발생한 StateError: No element를 해결했습니다.
- 원인은 목업의 지정 상품 ID와 실제 MySQL 상품 ID가 다를 때 빈 목록의 first를 읽는 코드였습니다.
- 상세 기획전도 홈과 공통 상품 선택 함수를 사용합니다.
- 지정 ID가 있으면 지정 순서대로 표시하고, 일치 항목이 전혀 없으면 현재 상품 일부를 대체 표시합니다.
- 상품 자체가 없으면 빈 목록 안내를 표시하며 알 수 없는 기획전도 안전하게 처리합니다.
- 기획전별 상품 지정은 아직 목업 ID 기준이며, MySQL의 별도 기획전 관리 기능은 구현되지 않았습니다.
- 상품 목록의 SIZE 펼침 예시 문구는 별도 개선 대상으로 남아 있습니다.
