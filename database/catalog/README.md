## 등록 방법

백엔드 의존성이 설치된 Python으로 `backend` 폴더에서 실행합니다. 연결 대상은 해당 백엔드의 환경 설정을 따릅니다. 먼저 읽기 전용 미리보기로 DB 대상을 확인하세요.

```sh
python import_initial_catalog.py
```

다음은 **로컬 `127.0.0.1`의 `shupick_v2`**에 적용하는 예시입니다. 팀 DB에 적용할 때는 담당자와 협의하고 미리보기의 실제 호스트·DB 이름을 명시해야 합니다.

```sh
# 전체 등록 과정을 검사한 뒤 롤백
python import_initial_catalog.py --check --expect-host 127.0.0.1 --expect-database shupick_v2

# 검사 성공 후 실제 등록
python import_initial_catalog.py --apply --expect-host 127.0.0.1 --expect-database shupick_v2
```

`--check`는 데이터 변경을 롤백하지만 MySQL 자동 증가 ID에는 빈 번호가 생길 수 있습니다. 상품 ID는 고정값으로 사용하지 마세요.

## 기존 데이터와 재실행

- 기존 `NK-M-SN-0001`, `TEST-ACCOUNT-A`, `TEST-ACCOUNT-B`, `TEST-ACCOUNT-C`는 판매 비활성화만 합니다. 상품·옵션·기존 주문 이력은 삭제하지 않습니다.
- 등록은 하나의 트랜잭션으로 처리합니다. 실패하면 DB 변경을 롤백합니다.
- 같은 카탈로그가 이미 등록되어 있으면 `already_present`로 끝나며 재고를 초기화하지 않습니다. 일부만 존재하거나 주요 값이 다르면 덮어쓰지 않고 오류를 냅니다.
- 이 도구는 최초 등록용입니다. 등록 후 JSON만 수정한다고 기존 DB 가격·사진 등이 업데이트되지는 않습니다.
- 적용 직전의 기존 상품 정보는 `backend/.local/catalog-backups/`에 보관하며 Git에서 제외합니다. 이는 전체 DB 백업이 아니라 비활성화한 상품 정보를 확인하기 위한 기록입니다.
- Git으로 코드를 받는 것과 DB 데이터 등록은 별개입니다. 팀원이 별도의 DB를 쓴다면 해당 DB에도 이 등록 과정을 진행해야 합니다.

등록 후 `/products`에서 상품 10개, 각 `/products/{id}/options`에서 옵션 5개를 확인하세요. 앱을 다시 시작하면 새 상품 목록을 불러옵니다.
