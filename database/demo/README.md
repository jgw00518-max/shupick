# SHUPICK MySQL 임시 데이터 제안

작성일: 2026-10-05
상태: 검토용 SQL 초안. 실제 DB에는 적용하지 않음.
대상: 현재 shupick_v2의 실제 스키마와 고객·직원 FastAPI.

## 파일

전체 SQL: [shupick_demo_20261005.sql](shupick_demo_20261005.sql).
마이그레이션 폴더 밖에 두었으므로 백엔드 마이그레이션으로 자동 적용되지 않는다.
기존 database/shupick_v2_seed.sql은 초기 스키마용이며, 현재 제거된 비밀번호 컬럼 등이 있어 이번 데이터 추가에 사용하지 않는다.

## 직원 업무 시나리오

기존 활성 대리점 SEL-SD(성동)와 SEL-GN(강남)에 홀수·짝수 주문을 배정한다.
본인 대리점 배정과 기존 권한에 따라 접근한다.

| 주문번호 | 건수 | 현재 상태 | 다음 업무 |
|---|---:|---|---|
| DEMO26-O001~006 | 6 | PREPARING | 본사 출고 |
| DEMO26-O007~012 | 6 | SHIPPING | 대리점 도착 처리 |
| DEMO26-O013~018 | 6 | READY_FOR_PICKUP | 주문번호 확인·고객 인도 |
| DEMO26-O019~030 | 12 | COMPLETED + 구매 확정 | 리뷰·포인트·고객 구매 이력 확인 |
| DEMO26-O031~036 | 6 | COMPLETED + 반품 REQUESTED | 검수 → 승인/거절 → 승인 건 환불 |

각 대리점에 출고 대기 3건, 배송 중 3건, 수령 대기 3건, 수령 완료 9건과 반품 3건이 있다.
주문일은 최근 4~22일에 분산된다. 수령 완료는 실행 시점 기준 하루 전이며 반품 접수 기한 안으로 설정한다.
반품 검수 전이므로 반품 재고를 본사에 미리 복원하거나 환불 완료로 표시하지 않는다.

발주 요청자는 활성 HQ_STAFF 중 TEAM_LEAD/DIRECTOR를 겸하지 않는 첫 직원이다.
작성 당시 선택 대상은 REG-C6D1FF446F1048FB9ACF였다. 적용 결과에서도 선택된 코드를 보여준다.
초안은 요청자 본인만 제출할 수 있다.
팀장 대기 2건은 두 결재 단계가 PENDING이다.
이사 대기 2건에는 기존 팀장의 가상 승인 기록을 명시하고 이사 단계는 PENDING으로 둔다.
요청자는 승인자와 다르게 선택한다. 로그인 가능한 팀장·이사 계정이 해당 역할로 결재할 수 있다.

## 본인 로그인으로 고객 기능 확인

상품 목록과 상세는 비회원도 조회할 수 있다.
DEMO26-C01~C12는 DB용 가상 UID이며 Firebase 로그인 계정이 아니다.

고객 앱에서 먼저 로그인·고객 동기화를 완료한 뒤, SQL 맨 위의
`@shupick_demo_customer_uid`에 본인의 기존 customers.firebase_uid를 지정할 수 있다.

- NULL이면 가상 고객 12명을 생성한다.
- 기존 UID이면 1번 고객 자리에 해당 고객을 사용하고 가상 고객 11명을 생성한다.
- 기존 이름·이메일·전화번호·UID를 변경하지 않는다.
- 1번 고객에게 O001(출고 대기), O013(수령 대기), O025(리뷰 작성 완료), 미답변 문의 1건, 1,000P 적립을 연결한다.
- 기존 지갑 잔액을 초기화하지 않고 데모 적립만 더한다.

Firebase 계정 생성이나 직원 권한 변경은 SQL에 포함되지 않는다.

## 적용 절차와 재실행 규칙

현재는 실행하지 않는다. 검토 후 적용을 승인하면 다음 순서로 진행한다.

1. MySQL Workbench에서 대상 DB shupick_v2를 확인한다.
2. 필요하면 기존 테스트 고객 UID를 지정한다.
3. `SET @shupick_demo_apply = 0;`을 `1`로 변경한다.
4. DELIMITER를 포함한 전체 파일을 실행한다. CREATE/DROP PROCEDURE 권한이 필요하다.

기본값 0에서는 CALL이 오류로 중단되어 업무 데이터가 들어가지 않는다.
단, SQL 파일 자체를 실행하면 로더 프로시저 CREATE/DROP 메타데이터 변경은 발생한다.
CALL 오류에서 실행이 멈춰 로더가 남으면 다음 명령으로 로더만 정리할 수 있다.

```sql
DROP PROCEDURE IF EXISTS shupick_load_demo_20261005;
```

DEMO26/D26 접두사가 이미 있으면 중단하는 1회 적용 SQL이다. 재실행 시 덮어쓰기·삭제·반복 적립을 하지 않는다.
업무 데이터는 한 트랜잭션으로 추가하고 오류나 수량·금액·재고 원장 검증 실패 시 ROLLBACK한다.
롤백되어도 AUTO_INCREMENT 번호는 건너뛸 수 있다.
선택한 기존 고객의 지갑 적립을 제외하면 기존 업무 데이터를 수정하지 않는다.

## 확인 범위

실제 DB의 information_schema와 SHOW CREATE TABLE을 조회하여 INSERT 컬럼을 대조하고,
현재 상품·출고·도착·인도·반품·결재 API의 상태 조건을 확인했다.
DB에는 SELECT만 실행했다. SQL 실행 검증은 아직 하지 않았으며 적용 승인 후 진행한다.
